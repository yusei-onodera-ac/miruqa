# 将来の拡張（今回は作らなかったもの）

今回の実装は、**「1社に販売し、その顧客が使える」規模**を目標にした。次の項目は、意図的に、今回の範囲から外した。
複数の顧客に提供するとき（事業化の次の段階）に、必要になる。

**前提（対象範囲）**: 本サービスは、**開発中・リリース前のテスト環境を、その所有者が点検する**ためのもの。本番サイトや第三者のサイトへの使用は、対象外（禁止）。

| 項目 | なぜ必要になるか | 今回の代わり |
|---|---|---|
| 招待・多段のロール（owner／admin／member／viewer） | 顧客の組織が大きくなると、権限を分ける必要がある | 「1アカウント＝1組織」。ownerが、メンバーを追加する簡易な方式 |
| 組織の切り替え | 1人が、複数の組織（制作会社が、複数の顧客）を扱う | 1アカウント＝1組織 |
| APIトークン | CI/CDへの組み込み（リリースごとの自動点検）に必要 | 画面からの実行のみ |
| 管理者画面・メトリクス | 全体のコスト、失敗率、キューの状況を、運営が見る | ヘルスチェックと構造化ログ |
| 公平なスケジューリング・負荷試験 | 多数の顧客が同時に使うと、順番と公平さが必要になる | 同時実行は2件まで |
| 決済の連携（Stripeなど） | 実際に請求する | 使用量の計測と、内部記録としての請求書まで（模擬） |
| プラン変更のUI・請求履歴 | 顧客が自分で、プランを管理する | プランは1〜2種の固定 |
| 組織単位のデータの書き出し | 解約・監査への対応 | プロジェクト単位の削除と、バックアップ・復元 |
| 通知センター | 診断の完了・不具合の通知 | 画面での確認 |
| 英語UI・ダークモード | 海外展開・利用者の好み | 日本語のみ・ライトのみ |
| 依存関係の脆弱性スキャン・OWASP ASVSの網羅 | 運用時の継続的なセキュリティ管理 | 基本の防御（認証・CSRF・入力検証・SSRF対策など）のみ |
| OrcaRouter の Firewall・Guardrails の接続 | ポリシー評価・入力検査を、ゲートウェイ側でも行う | 自前のポリシーゲートと、自前のマスク処理 |
| スキャン画像のPDF（OCR）の仕様書 | 紙由来の仕様書への対応 | テキストのPDF・docx・md・txt |
| 操作列の記録と再生（再テストのコスト削減） | 継続利用で、コストを下げる（実測で効果が見えた「固定手順のコード実行」の延長） | 設計と、記録の土台まで |
| 社内・VPN内のテスト環境への対応 | 開発中のサイトは、社内やVPNの内側にあることが多く、クラウド版からは届かない | 公開ステージング（ベーシック認証あり）を想定。届かない環境は対象外。将来は、客の環境に置いて動かす形（エージェントの配布）か、送信元IPの固定 |
| 法務の確認（規約・プライバシーポリシー・同意） | 販売の前提 | 下書き（【要法務確認】）まで |

## 販売に向けた、人の作業（技術以外）
- 規約・プライバシーポリシー・特定商取引法表記の、法務の確認。
- 不正アクセス禁止法・業務妨害のリスクについての、専門家の助言（他人のサイトへの能動テストの扱い）。
- サービス名の決定と、商標・ドメインの確認。
- 決済サービスの契約、ホスティングの選定。
- 料金プランの決定（`docs/pricing.md` の試算を、判断材料にする）。
